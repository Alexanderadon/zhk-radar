**Дата:** 2026-07-22
**Автор:** Phase-0 lead (ЖК-Радар)
**Город:** Алматы

## ВАЖНАЯ ОГОВОРКА: cloud-IP против IP Алматы

Все пробы и все состязательные перепроверки (adversarial verification) выполнялись с **облачного дата-центрового IP**, а не с домашней машины пользователя в Алматы. Это влияет на выводы двумя способами (в обе стороны):

- **Ложно-негативные блокировки:** часть источников отдала 403 / пустой ответ / DNS-fail именно из-за облачного IP, а с резидентного IP Алматы почти наверняка откроется. Затронуты: `homsters.kz` (403 Cloudflare), `homeportal.kz` (пустой SPA-шелл — это client-render, не блок), `adilet.zan.kz` (TLS cert error), сейсмо-портал `xn----ptbgks9a.kz` (DNS ENOTFOUND), `data.egov.kz /api/v4` (403 — вероятно нужен apiKey). Их нельзя считать «окончательно недоступными» — пользователь обязан перепроверить локально.
- **Ложно-позитивная лёгкость captcha:** `office.sud.kz` (суды) отдаёт reCAPTCHA v2. С облачного IP чекбокс почти гарантированно вызовет image-challenge; с резидентного IP Алматы чекбокс часто проходит в один клик. То есть с локальной машины доступ **проще**, чем показала проба.

**Обе gate-критичные источника (korter.kz и khc.kz) отдали чистые HTTP 200 с облачного IP без гео-гейта — значит из Алматы они гарантированно откроются как минимум не хуже.**

## Два gate-источника: вердикт состязательной проверки

Правило гейта: **ЖК-каталог И реестр гарантий КФГЖС** — два несущих источника. Оба прошли по два независимых состязательных прогона (accessibility + refutation).

### Gate 1 — Каталог ЖК = **korter.kz**

- **Состязательная проверка: `holds: confirmed`, `confidence: high` — оба прогона (accessibility и refutation).**
- Скептик перефетчил все ключевые URL и воспроизвёл **каждое** несущее утверждение: listing HTTP/2 200, 343 КБ, nginx, без Cloudflare/WAF/login; `window.INITIAL_STATE` присутствует; `filteredBuildingIds` = ровно **979**; реальные координаты Алматы; пагинация `?page=N` работает; detail отдаёт класс здания (IV класс эконом) + паркинг + застройщик; robots.txt запрещает только внутренние `/api/`,`/pyapi/` — HTML-страницы каталога/detail разрешены; class-сегментированный sitemap подтверждён.
- **Опровергнуть ядро не удалось.** Уточнения (не меняют вердикт «core»): (a) на странице есть ключ reCAPTCHA **v3** — но он гейтит только лид/контакт-формы, НЕ чтение каталога (данные пришли на чистом 200); (b) 979 — это building-объекты, не уникальные ЖК (~223) → дедупить до комплексов на этапе сборки; (c) robots.txt ≠ ToS: korter — коммерческий международный аггрегатор, общие Terms вероятно ограничивают bulk-скрейп; данные цен/сроков — маркетинг застройщика (оптимистичные сроки), НЕ ground truth для риск-скора.
- **Итог: SOLID.** Один korter.kz засеивает всю карту.

### Gate 2 — Реестр гарантий = **КФГЖС / КЖК (khc.kz)**

- **Состязательная проверка: `holds: confirmed`, `confidence: high` — оба прогона.**
- Скептик скачал и распарсил оба PDF локально. Воспроизведено: листинг отдаёт оба href; строящийся реестр (764 КБ) — заголовок «...По состоянию на 25.06.2026 · Всего договоров: 44», **ровно 5** строк «Гарантийный случай»; колонки №/№ДОГОВОРА/ДАТА/ЗАСТРОЙЩИК/УК/ОБЪЕКТ/ЭТАЖНОСТЬ/ПЛОЩАДЬ/КОЛ-ВО КВ/СРОК; ДПГ-YY подтверждены; ЖК «Каспий» / ТОО SMR-EURASIA / г. Алматы найдены дословно; завершённый реестр (1.6 МБ) — «Всего договоров: 245», колонка РЕГИОН присутствует.
- **Опровергнуть ядро не удалось** ни по одному из 4 углов (auth / завышенное покрытие / неструктурность / юр. риск).
- **Критичные build-поправки (парсер):**
  1. **`pdftotext -layout` НЕДОСТАТОЧНО** — кириллица рендерится квадратами; обязательно `pdftotext -layout -enc UTF-8`. Латиница/цифры/даты извлекаются в любом случае. Это флаг парсера, не проблема доступа.
  2. В строящемся реестре буквальная строка «Действующий договор» встречается лишь **1 раз** — парсер должен считать позитивным маркером **«Гарантийный случай»**, а всё остальное — активным по отсутствию флага (не искать метку «Действующий»).
  3. PDF-href — ротируемые хеши под `/upload/sprint.editor/`; **не хардкодить** — каждый прогон скрести листинг `khc.kz/ru/equity/uslugi/357/3260/`.
  4. Строки многострочные — якорить по паттерну `ДПГ-YY-...`, не по строкам.
  5. РЕГИОН иногда = регион ХQ застройщика, а не объекта — фильтровать Алматы по адресу в колонке объекта, не по РЕГИОН.
  6. Реестр — месячный снимок (25.06.2026), рефетчить по расписанию.
- **Ограничение охвата:** гарантия КЖК — лишь 1 из 3 легальных путей привлечения средств дольщиков (гарантия / банк 2-го уровня / разрешение акимата). **Отсутствие в реестре ≠ доказательство небезопасности.** Присутствие (и особенно «Гарантийный случай») — сильный сигнал; отсутствие — слабый. Это причина не задирать вес guarantee слишком высоко.
- **Итог: SOLID.**

### Вывод по гейту

**ОБА gate-источника — SOLID (оба состязательных прогона = confirmed / high).** По правилу гейта (оба solid → GO) это чистый **GO**.

## РЕШЕНИЕ: **GO**

**Оба несущих источника прошли состязательную проверку с вердиктом `confirmed / high confidence` на обоих прогонах.** korter.kz в одиночку засеивает всю карту (гео + класс + цена/м² + застройщик + статус стройки); КФГЖС/khc.kz даёт авторитетный государственный сигнал гарантии с готовым негативным флагом «Гарантийный случай». Ни один скептик не смог опровергнуть ядро ни одного из двух.

Это не «условный» и не «оптимистичный» GO: правило гейта требует, чтобы оба были solid — они оба solid. Остальные 4 компонента скора имеют рабочие источники разной сложности (courts и stop-construction — с трением доступа, но выполнимы; reviews и company-age — легко), и веса уже пересмотрены под реальную доступность, а не под желаемое.

**GO означает: концепт валиден, переходим к Phase 1 (сборка коллекторов). Никакого rework концепта не требуется.**

## Топ-рисков

1. **stop-construction без авторитетного поимённого списка Алматы** — самый слабый компонент. Держится на мониторинге новостей + NER + гео-привязке. Риск пропусков и (обратно) диффамации при ложном флаге. Митигация: **каждый** флаг стоп-строя обязан ссылаться на официальный акт (суд/прокуратура/акимат/гарант-случай КЖК), иначе не публикуется.
2. **Диффамационная экспозиция** (courts + stop-construction) — публичный «риск-скор застройщика» по счётчику исков/проблем без контекста (роль в деле, исход, отклонённые иски) приглашает иск от застройщика. Продуктовый, не технический риск. Митигация: показывать контекст дела, не голый счётчик; дисклеймеры.
3. **ToS/юридический слой** — krisha §5.3/5.4 прямо запрещают автосбор; 2GIS — non-commercial + запрет хранения; korter — общие Terms аггрегатора. Проект коммерческого намерения. Митигация: вежливый низкий rate, агрессивное кэширование, атрибуция, отзывы только как дайджест (короткие цитаты + deep-link), для запуска — запрос лицензии контента 2GIS.
4. **korter — маркетинговые данные** — сроки/статусы поставляются застройщиком (оптимистичны). НЕ использовать как ground truth для риск-скора; сроки/стоп-строй корроборировать официальным реестром.
5. **cloud-IP не равен Алматы** — часть fallback-источников (homsters, homeportal, adilet, сейсмо-портал, egov API) не проверена локально; captcha судов легче с резидентного IP. Пользователь обязан перепроверить всё «partial/fallback» со своей машины перед тем, как на них закладываться.
6. **captcha/JSF судов** — нет чистого облачного автофида. Придётся assisted-браузер с локальной машины по ограниченному списку застройщиков (десятки, не миллионы — выполнимо) либо платный агрегатор по БИН (Sensus/Kiberon) как fallback.
7. **PDF-парсинг КЖК** — обязательный `-enc UTF-8`, ротируемые href, многострочные строки, «Гарантийный случай» как позитивный маркер (не «Действующий»). Хрупко при неаккуратной реализации, но известно.

## Phase 1 — конкретные следующие действия (в порядке приоритета)

**Строить коллекторы в этом порядке (сначала два gate + дешёвые надёжные):**

1. **Коллектор korter.kz (каталог — ПЕРВЫМ).** Итерировать `?page=1..~49`, парсить `window.INITIAL_STATE.buildingListingStore.buildings` (20/стр: гео, цена/м², застройщик, constructionStatus, phone, slug), детерминированный brace-match. Затем detail по slug для `buildingLandingStore.attributes` (Класс/паркинг/этажность) — ИЛИ взять класс из class-сегментированных sitemap'ов (economy/comfort/business/elite). Без headless (SSR). Дедуп 979 объектов → ~223 комплекса.
2. **Коллектор КЖК/khc.kz (гарантия — ПАРАЛЛЕЛЬНО с №1).** Скрести листинг `khc.kz/ru/equity/uslugi/357/3260/` → текущие href обоих PDF → `pdftotext -layout -enc UTF-8` → парсить по якорю `ДПГ-YY`, «Гарантийный случай» = позитивный флаг дефолта, фильтр Алматы по адресу объекта. Расписание рефетча (месячный снимок).
3. **Извлечение БИН + company-age.** По ходу №1/№2 собирать БИН застройщиков; вывести возраст компании из БИН (кодирует дату регистрации). Дешёвый, надёжный компонент — закрыть рано.
4. **Join track-record.** Связать «застройщик → его ЖК» через КЖК-завершённый реестр (245, датированные) + korter developerBuildings + krisha. Кросс-валидация записей (record linkage) по name/район/цена.
5. **Коллектор krisha.kz (кросс-чек каталога).** `/complex/search/almaty/?page=1..61`, SSR HTML. Вежливый низкий rate + кэш + атрибуция (ToS-риск). Снапшотить еженедельно → цена-дельта + диф сроков сдачи (сигнал проскальзывания для stop-construction).
6. **2GIS reviews.** Резолв «ЖК → firm_id» (через каталог/suggest 2GIS, БРАТЬ firm-id из `/firm/`, НЕ geo-id!), затем `public-api.reviews.2gis.com/2.0/branches/{FIRM_ID}/reviews`. Хранить только score/count + короткие атрибутированные цитаты + deep-link (дайджест, не зеркало).
7. **Спайк homeportal.kz (АО КЖК Жилищный портал).** С локальной машины Алматы: headless-браузер, найти XHR/JSON-эндпоинты в DevTools. Это авторитетная БД легальности (разрешённые vs самострой) — успешный спайк апгрейднет stop-construction/guarantee к «core». Высокая ценность.
8. **Спайк судов office.sud.kz.** С локальной машины (лёгкая captcha): assisted-браузер, bootstrap JSESSIONID+ViewState, поиск по БИН из шага №3, пагинация, счёт актов + сохранение текстов. Оценить платный агрегатор по БИН (Sensus/Kiberon) как альтернативу для счётчиков.
9. **Мониторинг новостей (stop-construction, рекуррентно).** tengri/zakon/informburo/orda/kursiv: NER для имён ЖК, дедуп, гео. **Обязательная** привязка каждого флага к официальному источнику (контроль диффамации). Не разовый краул — событийный, по расписанию.
10. **База карты OSM + бенчмарк stat.gov.kz (контекст, низкий приоритет).** OSM Geofabrik KZ .osm.pbf (self-host Overpass, чтобы уйти от 429) для контуров/POI-ливабилити; taldau JSON API (найти indexId «цены на рынке жилья» + dics-коды) для медианной цены/м² → сигнал over/under-pricing. Оба score_component = none, но нужны для карты/контекста.

**Отдельно (перепроверить локально, не блокирует Phase 1):** homsters.kz (403 был cloud-only — возможный независимый источник отзывов), adilet/сейсмо-порталы, egov API с apiKey. Сейсмо-слой — разовая ручная оцифровка СП РК 2.03-31-2020 в QGIS → GeoJSON (fallback, не гейт).
