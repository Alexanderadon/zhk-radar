# /weekly — еженедельный ритуал обновления ЖК-Радара

Цель: обновить данные новостроек Алматы, честно показать что изменилось, задеплоить.
Модель runtime — как в jobhunter: интерактивная сессия Claude Code, не автономный батч (см. PLAN §4).

## Шаги

1. **Снять снимок «до»**: прочитать `data/zhk.json` (кол-во ЖК, распределение по бэндам) для сравнения.

2. **Прогнать коллекторы** (с локальной машины Алматы — важно, cloud-IP режут):
   - `node scripts/collect-korter.mjs` — каталог (SSR, без headless)
   - `node scripts/enrich-korter.mjs` — детали (класс/паркинг/этажность/сейсмика)
   - `node scripts/collect-kzhk.mjs` — гарантии КФГЖС (PDF → guarantees.json)
   - (опц.) `node scripts/collect-reviews.mjs` — дайджест 2GIS
   Коллекторы вежливые (throttle 500–800 мс). Ошибки не глотать — если korter сменил вёрстку, чинить `extract-state.mjs`.

3. **Diff**: сравнить «до/после» — новые ЖК, изменения статуса стройки, новые гарант-случаи КФГЖС, сдвиг риск-бэндов. Показать пользователю понятным списком, а не сырым git diff.

4. **Проверка на клевету**: если появился новый негативный флаг (гарант-случай, приостановка) — убедиться, что он привязан к официальному источнику. Без ссылки — не публиковать.

5. **Коммит**: `git add data/ && git commit` с сообщением вида `data: обновление радара DD.MM.YYYY (+N ЖК, M изменений статуса)`. История `data/` = аудит и юрзащита.

6. **Деплой**: `vercel --prod` (под fistin103, НЕ через Adam-логин — см. память deploy-setup). На сайте бейдж «данные от DD.MM» подтянется из `scrapedAt`.

7. **Отчёт пользователю**: 3–5 строк — что изменилось, есть ли новые красные флаги, ссылка на прод.

## Важно
- **Никогда не выдумывать данные.** Нет данных по фактору → серый, не красный (принцип как master-resume immutable в jobhunter).
- Скрейп остаётся локальным (гибрид): cloud-роутин может анализировать, но не скрейпить krisha/korter с датацентрового IP.
- Не пушить негативный флаг без ссылки на официальный акт (суд/акимат/КФГЖС).
